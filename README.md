## About

<img align="right" width="38%" src="https://raw.githubusercontent.com/Anmol-Baranwal/Cool-GIFs-For-GitHub/main/Programming.gif" alt="coding"/>

I am a **Full Stack Developer** who designs, builds, and ships production web applications end to end — from responsive component libraries to the REST APIs and database schemas underneath them.

I currently build a **B2B procurement SaaS platform** at One Link Tech, owning features across a **Next.js / React** frontend and a **Node.js / Express / MongoDB** backend. My work spans the full sourcing lifecycle — RFI, RFQ, RFP, forward and reverse auctions, and multi-round supplier negotiations.

I work at the intersection of **product engineering and applied AI**, integrating LLM capabilities directly into revenue-facing workflows rather than treating them as demos. I shipped AI into live RFP and RFI modules, cutting manual drafting effort for procurement users, and built an AI code review and repair engine on the Gemini API.

My engineering principles are consistent: **RESTful API design**, **JWT-secured architectures**, **scalable schema modelling**, **server-side pagination for list views that survive scale**, and **component-based frontends** verified across browsers and viewports. I write clean, reviewable, well-tested code and ship it through Git branch-and-review workflows alongside cross-functional teams.

| Attribute | Detail |

Deployed across Vercel and Render with independent frontend and backend lifecycles.

<br/>

A full-stack organisational management system modelling department–employee relations and self-referencing supervisor hierarchies, built for list views that stay fast as records grow.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | React.js · Node.js · Express.js · MongoDB · Mongoose · JWT · REST API · CORS |
| **Scale** | Server-side pagination and multi-criteria search engineered to keep list performance flat as record count grows |
| **Performance** | Indexed query paths, paginated payloads, and lean projections to minimise over-fetching |
| **Security** | JWT authentication across all protected routes, CORS policy enforcement, role-aware access boundaries |

The interesting modelling problem was the supervisor hierarchy: a self-referencing relationship inside MongoDB that must resolve reporting chains without recursive query explosions. Location filtering integrates the third-party CountriesNow API, normalised into the platform's own schema so the external dependency never leaks into the UI layer. Deployed across Render and Vercel.

</details>

<details>
<summary><b>Garib Khana — Free Game Aggregation Platform</b></summary>

<br/>

A live aggregation platform that normalises temporarily free game listings from multiple storefronts into a single consistent schema and interface.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | React.js · Next.js · TypeScript · JavaScript · Git · Vercel |
| **Scale** | Multi-source ingestion across Epic Games Store, Steam, GOG, and additional storefronts |
| **Performance** | Next.js rendering strategy tuned for fast first paint on a listing-heavy interface |
| **Security** | Typed boundaries at every external data ingress, defensive parsing of untrusted third-party payloads |
| **Impact** | Collapses fragmented storefront monitoring into one continuously refreshed source of truth |
| **Repository** | [garib-khana-web.vercel.app](https://garib-khana-web.vercel.app) |

The engineering core is normalisation. Every storefront exposes a different shape, a different notion of expiry, and a different reliability profile — the platform reduces all of them to one internal schema so the UI never branches on source. TypeScript enforces that contract at the boundary, which turns upstream API drift into a compile-time signal rather than a runtime failure.

</details>

<br/>

<details>
<summary><b>Mini Tailwind — Utility-First CSS Engine From Scratch</b></summary>

<br/>

A lightweight utility-first CSS engine implemented from first principles in vanilla JavaScript, generating styles at runtime with no build step.

| Attribute | Detail |
| :--- | :--- |
| **Stack** | JavaScript · HTML5 · CSS3 · MutationObserver API |
| **Scale** | Two-step DOM scanner covering both initial document parse and continuous runtime mutation |
| **Performance** | Observer-driven incremental style generation — only newly introduced class tokens trigger work |
| **Security** | Strict class-token parsing with no dynamic evaluation of user-supplied strings |
| **Impact** | Delivers utility-first styling to zero-build environments where a compiler step is not viable |
| **Repository** | [github.com/jemin7/my_own_Tailwind](https://github.com/jemin7/my_own_Tailwind) |

Built to understand what a utility framework actually does beneath the abstraction. The first pass scans the static DOM and emits the required rules; a `MutationObserver` then watches for dynamically injected elements and styles them at runtime. The result is a framework that behaves correctly in fully dynamic applications without a compilation pipeline — a genuine constraint in embedded widgets and legacy environments.

</details>
